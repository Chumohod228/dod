# Измерение максимального тока STS3215

Для сборки пирамиды двумя руками: [циклограмма и запись статичных поз](pyramid/README.md).

Для управления фолловером ID 1–6 от руки-лидера ID 7–12 используйте
`leader_follower.py`: [запись диапазонов лидера и запуск](LEADER_FOLLOWER.md).

**Применённая ручная калибровка:** смещения нуля и границы записаны в приводы,
актуальные диапазоны находятся в `limits.json` и автоматически загружаются при запуске.
ID 1: 683–3412; ID 2: 772–3322; ID 3: 863–3231; ID 4: 815–3280;
ID 5: 129–3966; ID 6: 1322–2772. Таблица из курсовой ниже оставлена как исходная справка.
Старые программы с прежними абсолютными позициями требуют обновления после изменения нуля.
Архив настроек и результат проверки:
`results/manual_ranges_20261009T105057_813610Z/applied_calibration.json`.

На этой прошивке запись цели положения может включать момент даже после `Torque_Enable=0`.
Процедура калибровки поэтому не записывает целевое положение; тест движения делает это
только после проверки всех приводов.

`servo_current_test.py` управляет шестью STS3215 через USB–TTL адаптер Waveshare,
задаёт случайные положения и сохраняет максимум модуля тока отдельно по каждому ID.
Python 3.10+, Linux или Windows. STM32 и программа `sender.c` для этого теста не нужны.

## Подключение и запуск

ПК → USB Waveshare Bus Servo Adapter → общая TTL-шина приводов с ID 1–6.
Сервоприводы получают штатное внешнее питание через адаптер. Адаптер должен работать
как прозрачный USB–TTL мост; для платы с ESP32 потребуется режим Serial Forwarding.
STM32 должен быть отключён от управления этой шиной. Закройте другие программы,
использующие порт: скрипт сам чередует команды движения и запросы обратной связи.

```bash
cd /home/chumohod/dod
python3 -m pip install -r requirements.txt
python3 -m serial.tools.list_ports
python3 servo_current_test.py --port /dev/ttyUSB0 --duration 60
```

Укажите именно порт USB-адаптера, а не виртуальный COM-порт ST-Link. В Windows:

```powershell
py -m pip install -r requirements.txt
py servo_current_test.py --port COM3 --duration 60
```

При системном запрете установки Python-пакетов используйте виртуальное окружение
(`python3 -m venv .venv`, `source .venv/bin/activate`) либо уже установленный `pyserial`.

**После запуска скрипт автоматически начинает двигать манипулятором.** Перед движением
он проверяет ответы всех выбранных ID, позиционный режим и начальные положения.
Если хотя бы один привод не отвечает, сообщает ошибку или находится вне диапазона,
движение не запускается. Начальная цель равна измеренному положению; затем включается
момент приводов и начинается случайное движение. EEPROM не изменяется.

## Диапазоны и движение

Диапазоны взяты непосредственно из `gamepad.c` курсовой:

| ID | Узел | Минимум | Максимум |
|---|---|---:|---:|
| 1 | База | 1023 | 3071 |
| 2 | Плечо | 1023 | 3071 |
| 3 | Локоть | 1023 | 3071 |
| 4 | Запястье | 1023 | 3071 |
| 5 | Вращение кисти | 1023 | 3071 |
| 6 | Схват | 1023 | 2047 |

Это отсчёты положения, не градусы. Индивидуальные границы не исключают столкновений
звеньев при произвольных сочетаниях углов. Для своей сборки задайте проверенные диапазоны
в `limits.json`; в курсовой плечо и локоть связаны одной осью геймпада, а здесь случайные
цели независимы. Сам скрипт не располагает геометрической моделью столкновений.

По умолчанию каждый привод получает случайную цель по всему рабочему диапазону,
на расстоянии не менее 35% ширины диапазона от предыдущей цели. Все цели отправляются
одной командой Sync Write. Пауза между целями — не менее секунды и не менее оценочного
времени перемещения при заданной скорости плюс 0,25 с. Это оценка, а не ожидание достижения цели. Скорость — 1000 отсчётов/с, регистр ускорения — 50. Для повторения
последовательности укажите одинаковый `--seed`; выбранный seed всегда сохраняется.

```bash
python3 servo_current_test.py --port /dev/ttyUSB0 \
  --duration 120 --limits limits.json --speed 1000 \
  --min-separation 0.35 --move-interval 1 --hz 50 --seed 42
```

Параметр `--min-separation` принимает долю 0..0.5. Полный размах уже включён
(`--max-step 4095`). Для небольших шагов задайте `--max-step 256 --min-separation 0`.
Ограничение `--max-step` имеет приоритет над минимальным расстоянием между целями. Скорость регулируется `--speed 1..4095`,
ускорение — `--acceleration 1..254`. Нулевые значения исключены, чтобы не включать
специальные режимы движения без ограничения скорости/ускорения.

`--ids 1 2 3 4 5 6` — список измеряемых и двигающихся приводов; по умолчанию все шесть.
`--timeout 0.03` — таймаут ответа одного ID; `--baud 1000000` — скорость порта.

## Результаты

Раз в секунду терминал выводит накопленные максимумы тока в амперах и отдельную
строку напряжения для каждого ID: последнее измеренное значение, минимум и максимум
за сеанс. При `status 0x01` сообщение об ошибке прямо указывает на ошибку напряжения
питания и содержит напряжение и ток в момент сбоя. Минимум сохраняется даже после
восстановления питания. Например: `ID 6: 5.1 V (min 3.5, max 5.2)`.
В новой папке
`results/<время_UTC>/` появляются:

- `peaks.csv` — максимальный модуль тока для каждого ID в мА и А, время и положение пика;
  последнее, минимальное и максимальное напряжение, время экстремумов, напряжение при пике тока;
- `samples.csv` — все успешные измерения: ток со знаком, его модуль, сырые данные,
  положение, скорость, напряжение, температура, признак движения и статус привода;
- `commands.csv` — заданные положения и время команд;
- `summary.json` — максимумы тока, последнее/минимальное/максимальное напряжение,
  полные отсчёты при минимуме и максимуме напряжения, конфигурация, seed, ошибки и результат завершения.

Папку можно задать через `--output my_test_01`; она должна быть новой, чтобы не затереть
прошлый тест. CSV измерений сбрасывается на диск средствами Python после каждого обхода,
сводки атомарно обновляются раз в секунду и при завершении. При аварийном отключении
питания ОС последние буферизованные записи всё же могут быть потеряны.

**Ctrl+C** завершает измерение и сохраняет результаты. Скрипт пытается прочитать свежие
положения и отправить их как цели удержания. Момент не отключается, чтобы рука не упала.
Если связь потеряна, программная команда удержания не гарантируется; приводы могут
дойти до последней заданной цели. Ошибка связи или ненулевой статус также завершает тест.
Корректный пакет с аварийным статусом сохраняется до остановки, включая значение тока.

## Что именно измеряется

Читается блок регистров 56–70 командой READ `0x02`. Ток находится в 69–70 (`0x45–0x46`),
порядок байтов — младший первым. Бит 15 — знак, младшие 15 бит — величина:

```text
signed_ticks = -(raw & 0x7FFF), если установлен бит 15; иначе raw
current_mA = signed_ticks × 6.5
peak_mA = max(abs(current_mA))
```

Запрос чтения только двух байтов тока для ID=1 выглядел бы так:
`FF FF 01 04 02 45 02 B1`. Скрипт читает более широкий блок, чтобы сохранять вместе с
током положение и состояние. Формат кадра: `FF FF ID LENGTH INSTRUCTION/PSTATUS PARAMS CHECKSUM`;
контрольная сумма — младший байт инверсии суммы от ID до последнего параметра.
Проверяются ID, длина, контрольная сумма; эхо запроса игнорируется.

Цели записываются через Sync Write `0x83`, broadcast ID `0xFE`, регистры 41–47:
ускорение, позиция, нулевое время, скорость. Это тот же протокол STS, что в курсовой,
с групповой записью вместо шести отдельных команд. Формат пакета геймпада `AA 55`
здесь не используется, поскольку STM32 исключён из цепочки.

Максимум считается по всему сеансу, включая исходное состояние и остановку; фаза
сохранена в CSV. Измерения с `moving=0` также учитываются: удержание нагрузки может
давать большой ток. Для анализа только движения отберите `phase=active` в `samples.csv`.
`--hz` задаёт желаемую частоту полного обхода, то есть каждого ID. Реальная частота
зависит от USB, времени ответов и числа приводов; она выводится при завершении.

Это **максимум встроенной телеметрии среди полученных отсчётов**, а не гарантированный
мгновенный электрический пик. Короткие пики между опросами могут быть пропущены,
случайный тест не гарантирует абсолютный максимум для всех нагрузок и поз.
Показания сервоприводов также не заменяют измерение общего тока источника питания.
Максимумы разных ID нельзя складывать и называть одновременным пиком всей руки.

## Проверка без оборудования

```bash
python3 -m unittest -v
```

Тесты используют эмулятор шины: проверяют пакеты, знак/масштаб тока, эхо, шум,
ошибки checksum, чужие ID, таймауты, диапазоны случайного движения, запись результатов
и остановку по ошибке. Проверка на физическом манипуляторе не выполнялась.
